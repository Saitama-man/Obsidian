Тестовые артефакты — это документы и результаты работы, создаваемые, используемые или изменяемые в процессе тестирования.
## Жизненный цикл тестовых артефактов

```text
Требования
↓
Анализ требований
↓
Тестовые сценарии
↓
Тест-кейсы / Чек-листы
↓
Test Suite
↓
Тестовые данные
↓
Выполнение тестов
↓
Баг-репорты
↓
Test Summary Report
```

---

# Test Scenario (Тестовый сценарий)

Высокоуровневое описание того, что должно быть проверено.

Отвечает на вопрос:

> Что необходимо проверить?

Примеры:

- Успешная авторизация.
- Вход с неправильным паролем.
- Вход с пустыми полями.

Тестовый сценарий не содержит подробных шагов.

---

# Test Case (Тест-кейс)

Подробное описание процедуры проверки.

Отвечает на вопрос:

> Как проверить?

Содержит:

- Предусловия.
- Шаги.
- Ожидаемый результат.

Пример:

Название: Вход с неправильным паролем

Шаги:

1. Ввести существующий логин.
2. Ввести неправильный пароль.
3. Нажать «Войти».

Ожидаемый результат:

Появляется сообщение «Неверный пароль».

---

# Checklist (Чек-лист)

Упрощенный набор проверок без детального описания шагов.

Пример:

- Проверить успешную авторизацию.
- Проверить пустой логин.
- Проверить пустой пароль.
- Проверить неверный пароль.

Используется для быстрого тестирования.

---

# Test Suite (Набор тестов)

Группа тест-кейсов, объединенных общей функциональностью.

Пример:

Test Suite «Авторизация»:

- TC-1 Успешный вход.
- TC-2 Неверный пароль.
- TC-3 Заблокированный пользователь.

Отвечает на вопрос:

> Какие тест-кейсы относятся к данной функциональности?

---

# Test Data (Тестовые данные)

Данные, используемые для выполнения тестов.

Примеры:

Валидные:

- user@mail.com
- Qwerty123!

Невалидные:

- abc
- 123

Граничные значения:

- 7 символов.
- 8 символов.
- 64 символа.
- 65 символов.

---

# Bug Report (Отчет о дефекте)

Описание найденной ошибки.

Содержит:

- Название.
- Шаги воспроизведения.
- Ожидаемый результат.
- Фактический результат.
- Severity.
- Priority.

Отвечает на вопрос:

> Что именно работает неправильно?

---

# Traceability Matrix (Матрица трассируемости)

Таблица связей между требованиями и тестами.

| Требование | Тест-кейсы |
|------------|------------|
| RQ-1 | TC-1, TC-2 |
| RQ-2 | TC-3, TC-4 |

Позволяет определить:

- Все ли требования покрыты тестами.
- Какие тесты затронет изменение требования.

---

# Test Plan (План тестирования)

Документ, определяющий стратегию тестирования.

Содержит:

- Объект тестирования.
- Область тестирования.
- Виды тестирования.
- Риски.
- Ресурсы.
- Сроки.

Отвечает на вопрос:

> Как будет организовано тестирование?

---

# Test Summary Report (Отчет о результатах тестирования)

Итоговый документ после завершения тестирования.

Содержит:

- Количество выполненных тестов.
- Количество успешных и проваленных тестов.
- Статистику дефектов.
- Вывод о готовности продукта к релизу.

Отвечает на вопрос:

> Каковы результаты тестирования?

---
